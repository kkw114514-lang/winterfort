## 1. 三层分离中 UI 的角色

UI **只显示、不算数值**。所有数值向逻辑层（单一信息源）订阅信号刷新；UI 仅把玩家操作（出牌/选目标/结束回合）转发给逻辑。下表是战斗 UI 全部显示数据的来源：

| 显示项 | 来源 | 现状 |
|---|---|---|
| HP / max_hp | `combatant.hp / .max_hp` | ✅ 字段有；刷新信号见 §10【需逻辑层支持 A】 |
| 能量 当前/上限 | `energy_changed(energy, energy_max)` | ✅ 信号有；公式待校正（§11） |
| 抽牌数 | `turn_started(.., draw_count)` | ✅；公式待校正 |
| 连击 | `card_played(card, combo)` | ✅（回合始归零见【D】） |
| 抽/弃/消耗 堆计数 | — | ❌【需逻辑层支持 C】 |
| 护盾 | `combatant.shield` | 字段有(=0)、无来源/信号【B】 |
| 状态层数（灼伤等级+层/中毒/力量/再生…） | `combatant.statuses[]` | ❌ 空，M2 落地【B】 |
| 敌人意图（当前+下回合 + 伤害预览） | `intent_locked(enemy, intent)` | 部分：只 `{type:"attack",power}` 单步【E】 |
| 卡面（费用/卡名/卡图/类型/描述/关键词） | `card.*` | 仅 name/cost/owner/effects【G】 |
| 回合数 / 楼层 | `turn_started(turn_number)` / 地图层 | 回合✅；楼层❌(M4)【J】 |

## 2. 整体布局（分层）

```
┌─ TopHUD ───────────────────────────────────────────────┐  (22,12)-(1258,50)
│  回合N           风雪城堡·回廊            第X层·节点    ⚙ │
├────────────────────────────────────────────────────────┤
│                    [World 层：背景 + 战斗单位]            │
│   ┌ Ally 纵深带(左) ┐              ┌ Enemy 纵深带(右) ┐  │
│   2号位(远·小·高)                        敌2(远·小·高)    │
│       1号位(近·大·低)                敌1(近·大·低)        │
│   (立绘+投影+血条+状态行)        (立绘+投影+血条+状态行+头顶意图)│
│                                                          │
│ ○能量      [连击×N]                              消耗○    │
│ 3/3                    [手牌·扇形]            [结束回合]  │
│ ▤抽牌堆                                          ▤弃牌堆 │
└────────────────────────────────────────────────────────┘
```

两层节点树：
- **World（Node2D）**：`Background`(z=-100) → `AllyFormation` / `EnemyFormation`（各持 `combatant_view`）。单位在世界坐标，做纵深缩放。
- **BattleUI（CanvasLayer）**：`TopHUD` / `UnitOverlay`（血条/状态/意图，跟随单位屏幕坐标）/ `HandArea` / `BottomLeft`(能量·连击·抽牌堆) / `BottomRight`(结束回合·消耗·弃牌堆)。

> 血条/状态/意图放 CanvasLayer 而非挂在世界单位下，是为了**不被单位缩放影响**、字号恒定清晰；它们的位置由"单位世界坐标→屏幕坐标"推出（formation 提供锚点）。

## 3. 可复用组件清单（component breakdown）

每个组件：**结构清晰、命名明确、可复用、布局走集中常量**（满足简报"UI 易改性"）。占位→icon 一一对应。

### 3.1 `combatant_view`（我方/敌方通用）
- **职责**：一个战斗单位的完整视图＝立绘 `Sprite2D` + 投影 + `health_bar` + `status_row` +（敌）`intent_view` +（被指定时）目标高亮环。
- **显示**：`combatant.name / hp / max_hp / shield / statuses[] /`（敌）`intent`。
- **数据来源**：初始化读 combatant；刷新订阅 §10 信号。
- **占位→icon**：立绘＝最终战斗 sprite（朝向：我方 facing right、敌方 facing left）；投影＝CSS椭圆→可换贴图。
- **易改**：`is_player`、`slot_index` 决定朝向与排布；尺寸/位置由 formation 给，**不在组件内写死**。

### 3.2 `health_bar`
- 细血条：底槽 + 填充（我方 `#2fae84` 青绿 / 敌方 `#c8313a` 绯红）+ 金色 1px 描边 + 居中文字 `hp/max_hp`。
- 来源：`combatant.hp/max_hp`。掉血走"先快后慢"补间 + 受击同步弹伤害数字（juice）。
- 护盾叠加：若 `shield>0`，血条左端叠一段冰蓝盾值（或在 status_row 出 `护盾` chip，二选一，建议血条左端 + chip 双显）。

### 3.3 `status_row` / `status_chip`
- 单位血条下方一行小 chip，按固定顺序排列（debuff 左、buff 右）；空时显示淡虚线"状态位"占位。
- **每个 chip** = 图标(16×16) + 数字。数字语义按状态分两类：
  - **灼伤**：显示 **等级（Ⅰ–Ⅳ）+ 层数（×N）**（两个数！灼伤是简报里唯一要双数显示的状态）。
  - 其余（中毒/力量/再生/虚弱/冰缓/护盾…）：显示**单个层数/数值**。
- **来源**：`combatant.statuses[]`【需逻辑层支持 B：状态数据模型 + statuses_changed 信号】。
- **占位→icon**：mockup 现用内联 SVG＋字 → 换 16×16 状态 icon 套（见 §6 状态清单，每个状态一个 icon + 主题色）。

### 3.4 `intent_view` / `intent_slot`（敌人头顶 · 双回合前瞻）
- 头顶并排 **2 槽**：左＝本回合（高亮、`now`）、右＝下回合（暗淡缩小、`next`）。每槽 = 意图图标 + 数值。
- 意图**锁死**（显示后不变，供预读）。
- **来源**：`intent_locked(enemy, intent)`【需逻辑层支持 E：意图结构化 + 双回合队列 + 伤害预览，详见 §7】。
- **占位→icon**：现用 SVG 剑 → 意图 icon 套（attack/defend/buff/debuff/special）。数值＝**结算后预览伤害**（逻辑层算）。

### 3.5 `card_view`（真卡面骨架 · 本轮重点）
见 §5 详规。结构：费用宝石 + 卡名 + 卡图窗 + 类型条 + 描述 + 关键词条 + 稀有度边框。

### 3.6 `energy_orb`
- 左下奥术能量球，显示 **当前/上限**（如 `3 / 3`）。上限＝耐力和+1（不结转）。能量为 0 的卡在手牌置灰。
- 来源：`energy_changed(energy, energy_max)`。占位→icon：CSS 球 → 能量球美术帧（可加流光/满能脉冲）。

### 3.7 `combo_view`（**v1 缺失，本规格新增**）
- 能量球右侧小牌匾 `连击 ×N`。每出 1 张 +1，回合末归零。
- 来源：`card_played(card, combo)`；回合始随 `turn_started` 归零显示【D】。
- 理由：简报数值口径明确要显示连击，`界面设计_v1` 整篇没有——补上。

### 3.8 `pile_view`（抽牌堆 / 弃牌堆 / 消耗堆）
- 抽牌堆（左下角）、弃牌堆（右下角）、消耗堆（结束回合右上紫色数字）。各＝图标 + 计数。
- 来源：**【需逻辑层支持 C：piles_changed(draw,discard,exhaust)】**。点击可弹"查看牌堆"列表（后续）。
- 占位→icon：现 SVG → 牌堆美术（一叠卡）。

### 3.9 `end_turn_button`
- 右下，金描边按钮 → 转发 `end_player_turn()`。敌人结算/动画期间置灰禁用。

### 3.10 `formation`（站位控制器 · 按 N 通用）
见 §4。

### 3.11 `top_hud`
- 细条：左＝回合数（`turn_started`）、中＝场景名、右＝楼层/节点（`第X层·N-M`【需逻辑层支持 J，M4 地图】）+ 设置入口。无"玩家总血"（肉鸽无此概念）。

### 3.12 juice 组件：`damage_popup` / `screen_shake` / `target_highlight`
- `damage_popup`：受击点弹跳大数字（灼/毒等 DoT 标色），来源 `damage_dealt(src,tgt,amount)`。
- `target_highlight`：持 A 类卡时，有效目标脚下亮**绯红可指定环**（mockup 已示，落在前排敌）。
- `screen_shake`：引爆/重击时屏震（表现层，不影响逻辑）。

## 4. Formation 站位系统（按 N 通用 · 绝不写死 2）

> 简报：常规 2 只 / 特殊关卡 3-4 / 联机更多；敌 1~5。公式按"速度和/耐力和"，站位按数量自动排布，**N=2 是当前特例**。

- **我方纵深带（左）**：定义纵深线 `近点 P_near → 远点 P_far`。给定 N，按 1号位(前)→N号位(后) 沿线插值：序号越小越靠**近点（下/右/大）**，越大越靠**远点（上/左/小）**。每只 `(position, scale)` 由插值算出。
- **敌方纵深带（右）**：同理，1~5 沿线自动排布；做**深度错位**（后排更小更高），避免并排显平。
- **集中可调参数**（放统一 `BattleLayout` 常量）：

| 参数 | 建议值（1280×720，mockup 实测） | 说明 |
|---|---|---|
| 地面线 GROUND_Y | ~500（脚底基线带 465–515） | 立绘 anchor 在脚底 |
| Ally `P_near` (1号位) | 约 (400, 515)，scale 1.00 | 近·大·低 |
| Ally `P_far` (末号位) | 约 (150, 455)，scale ~0.62 | 远·小·高 |
| Enemy `P_near` | 约 (838, 505) | |
| Enemy `P_far` | 约 (1110, 460) | |
| 单位最小/最大缩放 | 0.55 / 1.05 | 防 N 大时过小 |

- 血条/状态/意图**跟随各自单位**（由单位屏幕坐标 + 固定偏移推出）。
- **实现时机**：当前 2a-1 为静态手摆；接逻辑/做 `combatant_view` 阶段改为公式生成。
- **联机（远期）**：状态驱动 UI + formation 按 N，已为网络同步打底。

## 5. `card_view` 真卡面骨架（替换现纯黑+费用占位）

卡尺寸 **118×166**（圆角 9）。结构（从上到下，flex 纵列）：

| 区 | 内容 | 来源字段【需逻辑层支持 G】 |
|---|---|---|
| 费用宝石（左上） | 奥术紫六边宝石 + 费用数 | `card.cost`（已有） |
| 卡名（顶部居中） | 宋体金字 | `card.name`（已有） |
| 卡图窗（上中, ~54px） | 属性主题色底 + 卡图 | `card.art_key` + `card.element`（缺） |
| 类型条 | 攻击(绯红)/技能(湛蓝)/能力(金) | `card.type`（缺） |
| 描述 | 小字，关键词高亮 | `card.description`（缺） |
| 关键词条（底部） | 小标签：灼伤/消耗/引爆/炽核/留存/焚毁/余烬… | `card.keywords[]`（缺） |
| 稀有度边框 | 白/蓝/金/红 描边光 | `card.rarity`（缺） |

- **类型色**：攻击 `#c8313a`、技能 `#3f7fd0`、能力 `#c9a85f`。**稀有度色**：白 `#aeb4bd`、蓝 `#4f9fe0`、金 `#e0b24a`、红 `#d05a5a`。
- **状态牌**（如「余烬」）：用同骨架的灰调变体，标"消耗"，区别于正常牌。
- **能量不足**：整卡置灰 + 费用宝石变暗，不可拖出（逻辑判定 `energy < cost`）。
- **占位→卡图**：mockup 现用"属性渐变底 + 火焰 rune + 卡图占位"标签 → 换 `art_key` 指向的真卡图。
- 建议这些卡牌字段进**卡数据表 / `import_xlsx.py` 管线（M3）**，UI 只读不造。

## 6. 状态显示清单（status_chip 规格）

> 数据＝`combatant.statuses[]`【需逻辑层支持 B】。下表＝ UI 显示规则；机制以《机制关键词词典》为准。

| 状态 | 主题色 | 显示 | 备注 |
|---|---|---|---|
| 灼伤 | 橙 `#ff7a3a` | **等级 Ⅰ–Ⅳ + 层数 ×N**（双数） | 等级=易伤%（Ⅳ=+100%），层数=持续回合；引爆读 等级×层 |
| 中毒 | 绿 `#7fe07a` | 层数 ×N | 回合末造 N 伤后 −1 |
| 印记/易伤 | 紫 | 层数 ×N | 暗系易伤器（做暗系再上） |
| 力量 | 金 `#ffcf5a` | 层数 ×N | 本场永久，+10威力/层 |
| 护盾 | 冰蓝 `#7fd4ff` | 数值 | 回合始归零；带「留存」不清 |
| 再生 | 青绿 | ×N（回合） | 回合始回血 |
| 虚弱 | 灰蓝 | ×N（回合） | 敌输出 −25%/级 |
| 冰缓 | 浅蓝 | ×N | 敌意图伤 −15%/层 |
| 冻结 | 白蓝 | 回合数 | 跳过意图，意图槽叠"冻结"标 |

- 排序：debuff 左 → buff 右；超过 N 个折叠为 `+k`。
- **占位→icon**：每状态配 16×16 icon（统一像素风描边 + 主题色）。

## 7. 敌人意图显示（双回合 + 伤害预览）

- **双回合**：每敌头顶 `[本回合][下回合]` 两槽，本回合高亮、下回合暗淡。**意图锁死**。
- **意图类型 → 图标**：attack(剑) / defend(盾) / buff(上升箭) / debuff(下降箭/骷髅) / special(法阵)。mockup 现仅 attack。
- **数值＝结算后预览**：如目标带灼伤Ⅱ → 敌打 12 实际 15，槽内应显示**15（预览值）**，否则与实际不符；带我方冰缓则显示减后值。**此预览计算属逻辑层**。
- **目标提示**：意图可加"指向 1 号位"的细箭头/受击单位微高亮（敌固定打 1 号位，换人后打最新上场——见 §11 待校正4）。
- 【需逻辑层支持 E】：①意图含 `type / value / target_id / icon_key`；②维护 `[current, next]` 双回合队列随 `intent_locked` 一起发（现 `Battle.gd` 只存 1 个 intent，双回合前瞻**未实现**）；③`value` 为预览结算值。

## 8. HUD 数值口径（按简报最新 · 校正 v1）

| HUD | 新口径 | v1/代码现状（旧） |
|---|---|---|
| 能量上限 | **耐力和 + 1**；基准对子 = **3/3** | v1 写 4/4，代码 `耐力和−1`（待校正3） |

| 连击 | 出牌+1、回合末归零，**需显示** | v1 无连击显示 |
| 消耗堆 | 计数；本版无消耗卡恒 0 | ✅ |

- **手牌扇形**：≤5 张 span 17°/步距 96；>5 张自动收窄（span 22°/步距 74、加大重叠），整组夹在安全带 `x∈[260,1010]` 内，**不压能量/结束回合**。9 张 mockup 已验证不碰按钮。

## 9. 交互流程（沿用 `界面设计_v1` 拖拽方案，本规格只接缝）

完整拖拽/点击跟随/取消/消歧/物理手感 **以 `界面设计_v1` §四~六为准**，不重写。本规格补充与新组件的衔接：

- **A 类（需目标）**：拖卡到敌身上 / 点卡→点目标。持卡时**有效目标脚下亮绯红环**（`target_highlight`）。多敌时由玩家选；**【需逻辑层支持 F：play_card(card, target)】**。
- **B 类（无目标）**：拖出手牌区即出（全体/对己）。**【需逻辑层支持：effect target 类型 enemy/all_enemies/ally/self；界面设计_v1 §八已提 all_enemies】**。
- 出牌即时反馈：能量球扣减、连击 +1、弃牌堆 +1（飞牌动画）、命中弹伤害数字 + 视情屏震。
- 能量不足卡置灰不可出（逻辑判定）。
